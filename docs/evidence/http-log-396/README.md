# HTTP 通信ログ（#396）の検証記録

`--http-log-dir` の出力（stderr と `http.jsonl`）を、公式簡易サーバーの前に置いたプロキシが実際に見た通信と照合した結果です。ハーネスは [`ops/honsen/e2e.py`](../../../ops/honsen/e2e.py) の `--record`（試合記録と HTTP ログを両方有効にする）、要約は [`runs/`](runs/) にあります。

- 実行環境: macOS arm64、release ビルド、公式簡易サーバー `procon-server-darwin-arm64`
- candidate: `fleet:budget=official:budget_ms=10000`、`--kinds-auto`、1 日 12 秒、4 日
- **Windows では実行していません。**

## 照合した内容

1 つでも合わなければ FAIL です。

- `http.jsonl` の往復の数が、プロキシに届いたリクエストの数と一致する
- 各往復のメソッドとパスが、プロキシの記録と順番どおりに一致する
- `POST` の `request_body` が、プロキシに届いた本文と一致する
- 障害を注入していない往復の `status` が、プロキシが返したステータスと一致する
- 切断を注入した往復が `failed` として記録されている（成功として書かれていない）
- `http.jsonl` の各往復の見出し行と、送受信の本文の全文が、コンソール出力に含まれる
- `http.jsonl` にもコンソール出力にもトークンが含まれず、`[MASKED]` が出ている
- 試合記録（#394）の照合もすべて通る

## 結果

| 実行 | 盤面 | 注入した障害 | 結果 |
|---|---|---|---|
| `http16` | 16×16・4 台 | なし | PASS（4 / 4 日受理、不一致 0） |
| `http24` | 24×24・5 台 | なし | PASS（4 / 4、不一致 0） |
| `http32` | 32×32・8 台 | なし | PASS（4 / 4、不一致 0） |
| `s503` | 24×24 | 2 日目の `POST /` に 503 を 2 回 | PASS。`503 Service Unavailable` が 2 行、続いて `200 OK` |
| `drop-before` | 24×24 | 1 日目の `POST /` を転送前に切断 | PASS。`FAILED request` のあと再送が `200 OK` |
| `drop-after` | 24×24 | 1 日目の `POST /` の応答を切断 | PASS。同上（サーバーは受理済みだが、応答を受け取れなかったので `failed`） |
| `badjson` | 16×16 | `GET /` の応答を HTML に差し替え | PASS。`200 OK` と本文、続いて `DECODE ERROR` |
| `delay` | 16×16 | `GET /` の応答を 7 秒遅延 | PASS。`FAILED timeout (5001 ms)`、次の試行が `attempt=2` で `200 OK` |
| `kill-before` | 16×16 | 2 日目の回答前に `kill -9`、再起動 | PASS。run ごとに `http.jsonl` ができる |

## 単体・統合テスト

`crates/cli/tests/http_log_e2e.rs`（実 HTTP サーバーに対して実行）:

- 200 / 400 / 401 / 500（クライアント内部の再試行 3 回ぶん）/ タイムアウト / JSON でない 200 / 接続先なし を、それぞれ起きたとおりに記録する
- コンソール出力が `http.jsonl` の全行を整形したものと完全に一致する
- 8 台 × 400 手の `POST` 本文が、欠けずに記録され、サーバーが受け取った本文と一致する
- サーバーが 401 の本文・`Set-Cookie`・独自ヘッダーでトークンを返しても、どこにも出ない
- ログの有無で、試合の結果とサーバーに届いた全リクエストが一致する
- ログのファイルに書けなくなっても、リクエストは成功し、コンソールへの表示は続く
- コンソールが出力を受け付けなくなっても、リクエストは成功し、`http.jsonl` への保存は続く
- 応答の本文が途中で切れた場合、ログの有無で結果とリクエスト回数が同じになる（2xx の `GET /`、2xx の `POST /agent`、503 の 3 通り）

## 回答時間

`GET /` を受けてから受理までの秒数（プロキシ側で計測、日ごと、試合記録と HTTP ログを両方有効、3 試合同時）。

| 盤面 | 記録・HTTP ログあり | なし（[`../record-394/`](../record-394/README.md)） |
|---|---|---|
| 16×16 | 0.596 / 0.596 / 0.596 / 0.593 | 0.593 / 0.593 / 0.594 / 0.591 / 0.592 |
| 24×24 | 2.586 / 2.588 / 2.588 / 2.587 | 2.585 / 2.586 / 2.585 / 2.585 / 2.585 |
| 32×32 | 6.423 / 5.986 / 5.998 / 5.982 | （1 日 14 秒の設定で計測したため比較できない） |

16×16 と 24×24 の差は 1〜5 ms で、実行間のばらつきの範囲です。32×32 は 1 日 12 秒の設定で探索時間が短くなるため、14 秒設定の「なし」の値とは比べられません。締切までの余裕は、どの盤面のどの日も 5.2 秒以上ありました。
