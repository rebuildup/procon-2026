# supply-375 — 補給・巡回の同時最適化（Issue #375 / stacked on #372）

親 candidate: `fleet:budget=official:iters=N:chains=K`（branch `371`、SHA `5ddb153a16d44bb34c2c3ed5cea4aa8044f95bf0`、PR #372）。

## 仮説

`fleet` の補給モデルは 3 点で公式ルールより狭い:

1. **巡回車 1 台あたり 1 日 1 回の給油**。`Solution.serve[s]` は巡回車の順序リストで、`mutate` の移動は `retain` で重複を消すため同一巡回車が 2 回給油される構成は表現できない。
2. **会合セルはスポット訪問点（または stall 地点）のみ**。公式ルールは移動中の経路上セルでも、補給車と同じ反射 Tick を共有すれば給油できる（`refill_fuel_if_supply_present` は毎反射で全エージェント位置を見る、`supply_contact_keeps_patrol_moving_after_refill` テスト参照）。
3. **待機は stall のみ**。燃料切れで止まった巡回車はその場で補給車を待つが、「先へ進んでから待つ」対「待機してでも集める」のトレードオフは探索されない。

これらを緩和した同時最適化で公式 V→D→B が向上する解が実在するか、まず小型盤面（16×16）で存在証明を行う。

## 計画

1. 待機構造の定量化: 自前リプレイの Tick データから、巡回車ごとの給油待ち時間と到達後遊休時間を抽出する。
2. 存在証明: fleet と緩和モデル（複数回給油＋経路上会合）を同じ予算で 16×16（および手がければ 24×24）盤面に流し、公式 MatchSim の V→D→B を比較する。勝つ解が緩和機構を実際に使っているか（1 日複数給油・経路上会合の回数）をリプレイイベントで確認する。
3. 否認の場合: この README に却下証跡を残して PR を Close する。
