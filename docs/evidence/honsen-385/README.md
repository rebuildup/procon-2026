## 運用コマンド経由の通し（`honsen`、local プロファイル、16×16・5 日・10 秒/日）

1. 誤ったトークンで `preflight` → `401 AuthError` を検出して NG
2. 正しいトークンで `preflight` → OK（時計のずれ 1 s）
3. `start local` → 起動、`POST /agent` 受理
4. 2 回目の `start local` → 「二重起動はできません」で拒否
5. 試合中に coordinator を `kill -9` → 監視プロセスが 1 秒後に再起動し、`match already in progress: resuming … kinds=S,P,P,P` で同じ日から再開
6. 5 日すべて受理（サーバーログの `actions submitted` 6 回 = 5 日 + 再回答 1 回）、終了コード 0、`status` は「試合完了」
7. 車種の締切後（サーバー起動 7 秒後、締切 2 秒）に初めて `start local` → 簡易サーバーは未提出チームを全車巡回 `P,P,P,P` として扱い、v2 はその構成で 1 日目から参加して 5 日すべて受理。車種を選べないぶん不利なので、起動は締切前に済ませる
8. `set-server official` に Arena のホスト、`127.0.0.1` を指定 → どちらも拒否。`preflight arena` → 拒否

## 実施していない試験

- **本選サーバーへの接続**。URL もトークンも未受領。認証・時刻・応答形式が簡易サーバーと同じかは未確認
- **他チームが動く試合**。簡易サーバーでは相手 9 チームが回答しないので、渋滞の出る盤面での受理は Arena の実績（v1 と同じ探索、match 1960〜1968）に依る
- **ソルバの panic そのもの**。release ビルドは `panic = "abort"` なので、プロセス死（`kill -9`）からの復帰で代替した。同じ日に何度も落ちる場合、その日は失い次の日から復帰する
- **サーバーとクライアントの時計が大きくずれた状態**。`preflight` が 2 秒超のずれを FAIL にする。ずれた状態の試合は走らせていない
- **Linux / Windows 端末**。ビルドも実行も macOS arm64 のみ
- **試合途中での `rollback`**。v1 は途中再開できないため、手順上も試合の合間に限定した
