Design proposal · 01 of the layout track · rev v4

Layout — procon-2026 viewer

Structural proposal for the SolidJS + WebGPU match viewer. One shared 12-column grid; the shell and every route as bounded regions that close their own hierarchy with rows and hairlines — boxes only around units (one box per unit on the right-hand information rail, title inside; labels only where they carry meaning); sidebar as single-line icon + label tabs, state by icon and selection tone; tokens from Primer Primitives, UI icons from Primer Octicons. Geometry + contrast floors only — colour roles and interaction states are out of scope.

01

One grid system

12 fluid columns · demonstrated at 1280 and 420

Every section of this page and every panel inside the app sits on the same grid: 12 fluid tracks — repeat(12, minmax(0, 1fr)) — with every gutter and gap on the Primer space scale xs 4 · sm 8 · md 12 · lg 16 · xl 24. No per-section freestyle layout, no absolute positioning, no hard-coded pixel column width. Nested components use nested grid or flex and stay inside their outer column boundaries.

02

App shell

rendered 1:1 — 1280 × 800 · content shown: /live

The shell is a set of bounded sub-panels, not one document flow. Header and sidebar are fixed framing; main owns page scroll and nothing overlaps. Inside main the content band is left-aligned, max-width 1080, never centred. On the band's 12-column grid, each route places panels whose position, span and area carry the priority — and each panel closes its own hierarchy inside its outline. The eye lands on the map panel first on /live because it is the largest region, not because a heading told it to.

Map fit / centre rule (the fix). The frame must never be larger than the content it draws. Set the canvas viewBox to the board’s natural pixel size (mapPixelSize(map)), give the canvas width:100%; height:100% of the viewport and let preserveAspectRatio="xMidYMid meet" (SVG) / an equivalent uniform scale + centring translate (WebGPU) do the work. Initial camera = uniform fit with a 16px mounting gap on every side — spacing, not a stroke; zoom clamps relative to that fit scale; pan is clamped so at least 40 % of the board stays inside the frame. Corollary: never pass a synthetic width/height (today’s 800 × 420) as the viewBox — that is exactly what pins the 4 × 3 and 8 × 6 boards to the top-left corner.

05

Layout rules

extracted, not invented — every value traces to brief v4 or Primer Primitives
  1. 1Box only a unit. Divide with rows and hairlines. Label only when the label carries meaning. When a border is wanted, ask in order: (1) is this one unit? if not, do not box it · (2) does the inside really need further division? usually a row plus a hairline is enough instead of another box · (3) does its label change the reader’s understanding? if not, delete it. A row states one fact completely — fold two rows that complete in one. Group by meaning, not by visual evenness.
  2. 2One grid for the whole page and every section. repeat(12, minmax(0, 1fr)), column gap space.lg 16, panel row gap space.xl 24 — every gutter and gap is a Primer space token (xs 4 · sm 8 · md 12 · lg 16 · xl 24). No absolute positioning, no hard-coded pixel column width, no per-section freestyle layout. Nested components use nested grid or flex and stay inside their outer column boundaries.
  3. 3Shell and routes are bounded regions, not a content flow. Every route is a set of regions on the grid; each closes its own hierarchy with tone, gap and hairlines — not with an outline. Never stack “heading → prose → prose → table” down the page (brief v4 禁止 7). Priority = grid position + column span + area, never a nameplate.
  4. 4UI variant follows information priority. Primary → wide span + large value (26px). Secondary → one-line row, type locked to 11px / 15px. Tertiary → text link on a quiet region. Inside the match-state HUD every row is the same variant and the same two tiers, so HUD priority is span + position only.
  5. 5Shell. Header fixed 56px, sidebar fixed 200px with its own scroll, main is the single page-scroll owner. No region overlays another. Content band max-width 1080px, left-aligned, never centred.
  6. 6Navigation: role + priority + current location, by composition and colour. Role groups ORIENT / REVIEW / MONITOR above the fixed order Home / Replays / Solvers / Live. The monitor destination carries a priority sub-line of live values. Current item = selection tone (surface → surface-2) + weight + aria-current="page". Icon-led, inline SVG, no left accent bar, no colour-only state.
  7. 7Map fit / centre rule. viewBox = mapPixelSize(map) (natural size), canvas width:100%; height:100%, preserveAspectRatio="xMidYMid meet" / equivalent uniform transform in WebGPU. Initial camera = uniform fit minus a 16px mounting gap (spacing, not a stroke). Never pass a synthetic width/height as the viewBox.
  8. 8Density is a contrast, not a scale-down. Outer gutter space.xl 24 against dense gap space.sm 8 is the density strategy — the two must be separate tokens. Compressed: HUD rows, transport chrome, nav items. Never compressed: page gutter, panel row gap, the board’s fit inset, label letter-spacing.
  9. 9Breakpoints are content stress points, not device names. 960px — gap steps, gutter 24 → 16. 768px — sidebar repositions to a horizontal bar (labels, order, destination, current-state all preserved). 560px — gap sm 8 / row gap lg 16, HUD spans step up on the same 12 tracks. Long commands and paths wrap inside their region; the page never scrolls horizontally.
  10. 10Chrome and content show different border density. Chrome closes its bounded regions (header bottom, sidebar right, the mock frame) with boxShadow.thin. The content region carries exactly one boundary — the map instrument, because it is a different layer — and is otherwise divided by rows and hairlines only. Surface boundaries are drawn as box-shadow: inset 0 0 0 1px (Primer boxShadow.thin), never a layout-shifting border. Row hairlines are borderWidth.thin 1px. Accent marks state only; shadows are for floating elements only.
  11. 11Annotations are values, not prose. A note attached to a region shows a number with its unit or a measured quantity — viewBox 207.85 × 192, inset 16, span 8/12, 11 / 15 px, 30 · 31. Prose labels stuck to framed regions (brief v4 禁止 8) are deleted; if an explanation cannot be said as a number it goes in this rules list, not on the mock.
  12. 12Contrast floor (WCAG 2.x). Text and icons ≥ 4.5:1 against their background (large text 3:1); non-text graphics, markers, boundary lines and focus rings ≥ 3:1. Measured on this sheet — see the table below. Low contrast is not a style choice.

A row hairline is a decorative separator, not a graphical object that conveys information, so WCAG 1.4.11 does not apply; every boundary that does carry meaning (the map instrument, focus rings) uses borderColor.emphasis at ≥ 3.24:1.
!

Contradictions found — DESIGN-BRIEF v4 vs current CSS

every claim points at source under packages/frontend/src/
1 · The density contrast the brief requires has no token to express it Brief: “ページ外周は余白を取るが、HUD と表は詰める” and 外周ガター 24 / 密集部 8. theme.css defines one value, --app-pad: 1rem, and layout.css spends it on both the page gutter (.app-shell__main) and the panel padding (.page). Outer and inner density are the same number.
2 · Radius ceiling is breached by the token itself Brief caps controls at 4–6px and panels at 6–8px. theme.css defines --app-radius: 8px; it is applied to sidebar links and the theme toggle (layout.css), transport buttons (replay-viewer.css) and HUD cells (live.css) — every control sits at the panel upper bound. One value, controls and panels both.
3 · Static panels carry the elevation the brief reserves for floating elements Brief: “shadow は浮動要素のみ”. .app-header and .page (layout.css) and .replay-viewer (replay-viewer.css) all set box-shadow: var(--app-shadow), so every content card is raised — a second hierarchy channel competing with the board.
4 · The “does not break” responsive tier is decided but not implemented Brief: desktop-first, responsive only needs to not break. There are zero @media rules across layout.css / live.css / replay-viewer.css / map-viewer.css / theme.css / webgpu-map-viewer.css. At 420px today nothing reflows: the five-tile HUD and the 800px command line simply overflow.
5 · Navigation: accent fill as the marker, no icons, and a vacant list Brief v3 禁止 2 / 9: 現在地は icon + 選択トーン、構成は色と形の両方. layout.css paints .app-sidebar__link--active as a full-width --app-accent block (the brightest object in the chrome), and Sidebar.tsx renders flat text-only links — no icon, no role grouping, no current-location composition.
6 · Match-state HUD uses a type ladder inside one surface Brief v3 禁止 3 / 撤回 1: 同一 surface は同サイズ 2 段のみ. live.css sets .live__hud-value--large at 1.8rem, .live__hud-value--mono at 0.95rem, and leaves the plain value at body size — three tiers across DAY / REVISIONS / SOLVER / SERVER / LAST UPDATE.
7 · Status badge is a tinted fill with a same-colour border Brief v3 禁止 6 / 撤回 4: 無彩色 chip + marker. live.css gives each [data-status] a coloured background and a matching darker border-color (e.g. waiting #f5c542 + #d6a82b). The same block also holds the status L* spread the brief measures (waiting L*81.7 vs error L*45.9).
8 · The map viewBox is synthetic, not the board’s natural size Brief: viewBox = mapPixelSize(map). MapViewer.tsx does props.width ?? dims().width for both the attribute and the viewBox, and Live.tsx / Replays.tsx / Solvers.tsx pass width={800} height={420}. That synthetic size is exactly what pins the 4 × 3 and 8 × 6 boards to the top-left corner.
9 · Data encoding borrows UI chrome tokens Brief: data encoding は UI chrome と完全に分離. map-viewer.css strokes .map-viewer__cell with var(--app-border-strong), and types/map.ts sets AGENT_COLORS.supply: '#0969da' — byte-identical to --app-accent in theme.css.
10 · Dark muted text fails the contrast floor the brief itself states Brief v3 Typography: text/icon ≥ 4.5:1. Measured: --app-muted #7d8590 on --app-surface #161b22 = 3.04:1 (the brief’s own Evidence figure). Light #59636e on #161b22-equivalent surface passes, dark does not — and several labels use the even lighter end of the ramp. This sheet raises muted to 8.5:1 / 7.3:1.
11 · Brief v3 禁止 5 forbids outlines; v3 shell rules require bounded panels 禁止 5 says separate surfaces by tone + gap and keep strokes to the focus ring, while “shell はサブパネルで構成する” and the user review ask for visible table / panel outlines. Resolved here by explicit user instruction: hairline outlines at ≥ 3:1 bound panels and tables, tone + gap still group them, and no outline carries accent or decoration. Implemented as 1px solid var(--hair) on .panel / table.bp.
