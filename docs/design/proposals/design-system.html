Color — 間隔を数値で決める

CIELAB L* C* h · 4 chrome hues

現状の配色が「ただ気になっている」理由は、感覚ではなく計算で説明できる。 既存 live.css の status 4 色は L* が 45.9 – 81.7（ΔL* = 35.8）も開いており、黄色だけが発光して見える。 一方で GitHub 由来の 4 色は L* が揃っているのに C* が 54 – 75（ΔC* = 21）散っている。 明度だけ / 彩度だけを揃えてもトーンは揃わない。 この proposal は色相の距離を保ったまま、明度と彩度を固定する。

Neutral ladder — h と C* を固定し、L* だけを動かす

5 L* per rung

中立色は純グレーにせず h ≈ 258°（青寄り）を固定、C* 2.5 – 4.5 も固定。 rung の順序（surface > surface-alt > bg）と間隔（5 / 5、全域 10）は light と dark で完全に同一 — 反転ではなく同一の構造を別の絶対値で載せ直している。

surface — card / tile / row / active item light #ffffff · L*100.00  |  dark #31353a · L*21.96 ↓ Δ L* 5.05 / 5.10
surface-alt — band: header / card head / hover / zebra light #edf1f5 · L*94.95  |  dark #262a2f · L*16.86 ↓ Δ L* 4.91 / 4.85
bg — page canvas / inset well / gap between tiles light #dfe3e7 · L*90.04  |  dark #1c2024 · L*12.01 vs surface Δ L* 9.96 / 9.95

上の 3 帯は隙間も罫線も持たずに接している — 帯と帯の明度差そのものが境界。 最下段の bg は page と同じ色なので panel から外れて見えるが、 それ自体が「page と card の差 = 約 10 L*」の実演である。

Data encoding — 公式図の実測色を正とする

saturated · practical · measured
separate layer · theme-independent

v3 で判断を反転。 v2 が指示した低彩度（C* 24–30・L* 60 揃い）は 識別が逆に難しくなり失敗した。正解は公式資料の図1–4 に埋め込まれた色だった。 これらは彩度もコントラストも高いのに刺激的ではない — ネオンではなく 落ち着いた実用彩度（純粋な赤ではなく burnt orange #c04f15、 純粋な紫ではなく pastel pink #e59edd）だから。 低彩度化・等明度化は禁止。明度差は識別に有用として許容する。

Typography — 3 roles, 字組みで印象をつくる

sans / tabular / mono

font family の集合ではなく文字の役割で 3 つに分ける（typesetting §2）。 UI sans が構造とラベル、numeric-tabular が reading の主役である数値、 mono-command がコマンドと ID・アドレス。 色は合っていてもテキストの印象が微妙なときは色を動かさず字組みで直す — letter-spacing の規律、label case の統一、和欧混植の baseline / weight。

✓ 同一 surface は 2 段のみ — label 11–12px + value 15–16px。DAY だけ大きくする階層は撤回。 ✕ HUD 値が page title を上回る（旧案の 28px）ことは禁止。優先度はグリッド位置と列 span で示す。

12 col · tone + gap, never a stroke

04

Icons — 認知の主軸、text は補助

inline SVG · viewBox 16 / 24 · no network

icon が第一の認識軸、text ラベルは第二。GitHub の control を参照して 密度と抑制を学ぶ（brand 色・octicon の形は複製しない）。 icon は inline SVG のみ — icon font・外部配信・画像ファイル・ネットワーク取得を使わない。 viewBox は 16 と 24 の 2 系統だけ、path ノードは最小限。 これは RAM と初回描画を軽くするための制約であり、見た目の好みではない。

Family profile
✓ artboard 16（control）/ 24（広域）。 stroke 1.5（16）/ 2（24）、currentColor 継承のみ。 ✓ 角は round join / cap、コーナー r≈1.5。 stem 幅 2px で全 glyph の太さを揃える。 ✓ 光学サイズは 16 内で約 13px。全 icon 同一。単純スケールせず、小さいほど detail を削る。 ✕ 色を icon に持たせる、サイズごとに別 glyph を作る、複数 icon set を混在させる。

05

Marks — モチーフから始める、形が意味を運ぶ

3 motif families · pick one

v2 の「幾何塗り / 塗り+内抜き / 線画」は抽象幾何の派生であって互いの差が小さく、意味がなかった。 v3 で反転する。まず「それが何か」を絵で表し、その絵を簡略化する。 山は山に見え、水は水に見え、道路は道路（帯）に見える。 巡回と補給は役割が読める形。三角・菱形・円の並びを主軸にしない （現行 MapViewer の patrol=三角 / supply=菱形 は意味を運ばない）。 意味の違う符号同士は形も違う。 漢字ラベルはオプション overlay（既定 OFF）。符号が主符号化。 記号は icon 設計と同一規則（keyline / 光学サイズ / 線幅）に従い、実サイズで検証する。

A 稜線・波・帯 — 山容の稜線、水面の波、路面の帯。実景シルエットを簡略化。 B 峰・しずく・リボン — 地図記号の語彙。単峰＋ハッチ、水滴、経路のリボン。 C 段丘・水位計・レーン — 計器の語彙。標高の段、水位のゲージ、車線の矢印。
✓ 選択肢は別モチーフの簡略化案として並べる。同一モチーフの簡略度違いは選択にならない。 ✓ 各 family 内でも 役割ごとに形が違う（山≠水≠道、巡回≠補給、series 6 形も互いに別）。 ✕ 抽象三角・菱形・円を意味記号として使う。形が同じで色だけ違う、も不可。

Do / Don't

v3 反転判断の再発防止

各組の上段が NG、下段が本 proposal。1 組目は引き続き最重要の禁止（カード部分への accent 塗り）。 4 組目は v3 で反転した符号判断（抽象幾何 → モチーフ起点）の再発防止。 DESIGN-BRIEF.md v3「v1 からの撤回」と対応する。

✕ Don't — 面の断片に accent を塗る（AI slop）
edge strip（左端の色帯）
corner chip（角の色片）
accent border（同系色の輪郭）
partial fill（面の一部だけ塗る）

nav / tab の左 accent バー、selected の 4px marker、カードの上端ライン、 badge の tinted fill + 同色 border、hover に accent を敷くこと — すべて同種の禁止。

面の一部をアクセントで彩ることは、状態ではなく面を飾ること。 色の面積が無意味に増え、本当に状態を示したいときに色が効かなくなる。 解像度が変わるたびに「断片」の見え方も変わる。
✓ Do — 面は中立トーン、accent は状態だけ
edge strip なし — 明度差と gap で分ける
corner chip なし — 角は radius 3/4/6 のみ
border なし — 帯と帯の明度差が境界
Running focus

accent が残るのは primary button の塗りと 状態 marker だけ。 selection は icon + 選択トーン、focus は button-tone ring。

accent = 状態の表示のみ。面の装飾には中立 ladder（≥5 L*）と間隔（≥8px）を使う。 これが守られて初めて、status の 3 hue と primary の accent が画面で意味を持つ。

badge が色の面として存在すると、chrome の色数が増え、 本当に見せるべき status が埋もれる。丸い形状まで status 専用の語彙になるのも避ける。
