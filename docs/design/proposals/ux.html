Invariants

  • One authority. createReplayStore is the single source of truth. Controls render from the snapshot; none of them derives play state independently (interaction-state: state authority).
  • Mutual exclusion. status is derived: playing XOR {idle, paused, finished}. finished requires stepCount-1 > 0 — single-step replays never reach S3 (observed guard in stores/replay.ts status()).
  • Orthogonal overlays. S4 (scrubbing) and S5 (rate) never replace the base state. S4 exists precisely to forbid the impossible combination the current code allows: a drag that the timer overwrites on its next tick.
  • Disable set is pure. Derived from (currentStep, stepCount) only — never from rate, theme, or renderer mode.
  • Single-slot timer. The effect clears the previous interval before arming (ReplayViewer.tsx:58–75); rate spam cannot stack intervals.
  • Rapid input is normal path. Step ± while playing does not pause; the timer continues from the new step. Pause then Play within one tick resumes from the same step.
  • Transient ≠ state. S5 has identical interaction rules to any other state — modelled as feedback so it cannot produce a phantom state.

Renderer switch — SVG ⇄ WebGPU

The segmented control on /solvers (solvers-renderer-svg / solvers-renderer-webgpu) picks a renderer; WebGpuMapViewer decides what is actually painted. Those two answers can disagree — and under headless SwiftShader they do, silently. This section defines every branch, including the one the current code has no name for.

Known bug — Issue #259. The WebGPU canvas renders blank under headless SwiftShader (docs/evidence/258/README.md:14–16, visible in target/uishots2/3-solvers-webgpu.png as an empty 800×420 region). The GPU path initializes fine, so no fallback and no loading branch is shown — the user gets an empty box and no signal. This proposal gives that outcome a designed state: data-fallback-reason="blank-frame".

Keyboard & focus

Tab moves between meaningful components; composites own their internal keys (keyboard-interface: page traversal ≠ component-internal navigation). Every action stays reachable without shortcuts — shortcuts are an optional acceleration layer, documented in the UI, never a hidden requirement.

Focus ring spec (v2 — button tone, not the accent)

  • Exact values: outline: 2px solid var(--focus-ring); outline-offset: 1px; where --focus-ring = #6e7781 (light) / #8c959f (dark). A button-tone neutral — the same grey family as --border-strong / --muted, one step darker on light and one step lighter on dark. The accent (#0969da / #2f81f7) is withdrawn from focus (v1 used 2px + offset 2px + accent).
  • Functional requirement, not a preference. The indicator must remain distinguishable from the unfocused state, or keyboard operation breaks. This is why the ring is toned down to a button tone but not removed or faded into the border: measured against the control surface the ring holds 4.3:1 (light, #6e7781 on #f6f8fa) / 5.7:1 (dark, #8c959f on #161b22) — above the 3:1 non-text floor — while sitting clearly apart from the hover border (a brightness step, not a hue change).
  • Inside .map-viewer (overflow: hidden) use outline-offset: -2px so the 2px ring is fully inside and never clipped.
  • Never animate the ring (0ms) — it must appear in the same frame as focus.
  • Never use :focus — a mouse click must not leave a ring on a button.
  • Disabled controls keep the native disabled look (opacity: .45, replay-viewer.css:136–139) and leave the tab sequence — correct for plain buttons.

Composite model (unchanged from v1 — keyboard behaviour was accepted)

  • Transport buttons: native <button>, activation via Enter/Space.
  • Rate group: APG radio-group — role="radiogroup"/radio, roving tabindex, arrows move, selection follows focus (no expensive side effect).
  • Map: one composite stop, arrow keys pan, +/− zoom, 0 reset; focus entry lands on the composite, not on each hex.

05

Iconography — one family, icon-first

Replaces the current text glyphs (◀◀ / Play / ▶▶, ReplayViewer.tsx:145–162) with a single family shared by the transport set (play / pause / step / rewind) and the renderer set (SVG / WebGPU). Icons are the primary recognition axis; text labels are secondary (accessible name via aria-label, visible label only where it adds meaning). Density and restraint follow GitHub’s toolbars — 16px control glyphs, monochrome currentColor, few path nodes — without copying octicon shapes or GitHub brand colour.

Family profile (transport + renderer = one family; v2 withdrew the fill/outline split)

  • Artboards 16 and 24 only (viewBox="0 0 16 16" / "0 0 24 24"). No 20, no arbitrary scales. Render 16 from the 16 artboard, 24 from the 24 artboard.
  • One construction: solid silhouette (fill="currentColor") with a same-colour rounding stroke — stroke-width 1.5 on 16, 2.25 on 24 (identical optical weight, 0.094 of the artboard), stroke-linejoin/linecap: round.
  • Same corner treatment everywhere: rounded joins on polygons, rx 1.2 (16) / rx 1.8 (24) on rectangles. No square-corner icon sits next to a rounded one.
  • Optical size: painted content occupies 12u of the 16 artboard (75%), 18u of the 24. Play’s apex sits at x≈12.4 (16 grid) — right-biased so the solid triangle centres optically. Path node count per icon ≤ 4.
  • Colour: currentColor only. Disabled (opacity .45), hover and active work without redrawing. No icon carries its own fill.
  • Selected state is not colour alone: rate / renderer segments keep aria-pressed + filled accent surface (active state — the one place accent is allowed); glyph shape is unchanged.
  • Target ≠ glyph: 16px glyph inside a 32–36px control. Never shrink the hit area to the glyph.
  • Icon + text: the icon leads; label is secondary. 1× 2× 4× stay text (they are values, not actions). Transport actions are icon-only with aria-label + title.
  • Weight budget: inline SVG only — no icon font, no external file, no network fetch. This sheet carries 19 SVGs total (v1 had 29).

Clear-space tokens — the icon + its margin is the component (consumed by design-system.html)

  • --icon-size-sm: 16px · --icon-size-lg: 24px — the only two optical sizes. Do not render intermediate sizes; do not scale the 24 artboard down to 16.
  • --icon-clear-space: 2px — four-sided clear space. The icon’s layout box is glyph + 2px on every side; nothing (label, edge, badge) may enter it. Drawn as the dashed box in the specimen below.
  • --icon-label-gap: 6px — icon-to-label gap in an icon+text control (dense toolbar rhythm; 4px collides, 8px reads as a separate item).
  • --icon-control-min: 32px — minimum control dimension (hit target).
  • --icon-stroke: 1.5px — effective stroke at size-sm; ×1.5 at size-lg.
  • Centring rule: the control content box centres the icon with display:flex; align-items:center; justify-content:center. No optical nudge inside controls — silhouettes are pre-biased on the artboard (play’s apex etc.), so the family centres as a set. The padding box above is what gets centred, not the raw path bounds.

Motion spec

Level: functional minimal (brief). Motion exists only where it carries state change, continuity, or feedback — and never above 150ms. Feedback stays under 100ms so repeated clicks never queue. This spec was not revised in v2; it is restated so the new focus ring and badge treatments inherit the same rules.

Motion vocabulary (component-level; colour/type tokens stay in design-system.html)

--m-feedback: 90ms · --m-state: 120ms · --m-swap: 140ms · --ease-out: cubic-bezier(0.2, 0, 0, 1) · --ease-linear: linear (progress fill only)

Score table spec — alice / bob

Per table-design: the task is read + compare two player scores at the current step — lookup/comparison, no cell selection or editing → a native <table>, not an interactive grid. The 2D structure is preserved; there is nothing to recompose.

Column rules

  • Row identity: player id (alice / bob) as <th scope="row">.
  • Caption: Scores — demo-match (state().matchId.value, ReplayViewer.tsx:109).
  • player — left-aligned, text; score — right-aligned, integer, no unit, font-variant-numeric: tabular-nums, precision fixed per column.
  • Type: two tiers only (v2). Labels (caption, column heads) at 11px; values (player name, score) at 15px. No third size for “emphasis” — the score’s priority comes from right alignment and column position, not a larger font.
  • Missing value: em dash — (same discipline as STATUS_PLACEHOLDER, Live.tsx:71). Never an empty cell.
  • No delta column. F1-style red/green deltas are explicitly out of the brief’s colour discipline (DESIGN-BRIEF, References — do not copy).
  • Density: row height 32px (--app-row-h), 1px bottom border only, no zebra, no hover chrome — 2 rows, read-only.
  • Growth: if players > 8 rows, sticky thead inside the table’s own scroll region (never hide the scrollbar).
