### 5.1 32×32 official：探索量と成績（`fleet:…:chains=4:fuel_need=50:fuel_mix=on`）

**探索量固定**（`iters` を振る。2001・2004・2016 × seed 42・7 の 6 run、`results/official32-players2-iters-curve.jsonl` と `…iters600k.jsonl`、60k は 2b の `sized` の行）

| 600,000 | 319・326 | 472・469 | 298・298 | 2182 | +2.0% |

V・D は全条件で同じ（23/184、21/189、22/132）。seed 間の差は 0〜15 玉。**60 万回あたりで頭打ち**になる。

**wall-clock**（`budget_ms` を振る、seed 42、1 run ずつ。他の計測ジョブと同時に走ったので chain は CPU を取り合っている、`results/official32-players2-wallclock.jsonl`）

|---:|---:|---:|
| 5,000 | 297（再計測 299） | 323 |
| 20,000 | 299 | 326 |

- 5 秒で既に探索量固定の頭打ち水準（2016: 298〜303、2001: 314〜326）にあり、59 秒まで伸ばしても +1% 前後。**実戦の 59 秒は探索不足ではない。**
- 頭打ちの値は実戦の 1 位と同じ水準：2016 は 301 対 304、2001 は 327 対 321、2004 は 468〜481 対 475。「32×32 で 1 位に 5% 届かない」と見えていたのは、`iters=60000` での比較（頭打ちより 4% 低い）と燃料項なしの実戦値を比べていたためで、**この 3 盤面では、頭打ちの値と実戦 1 位のあいだに経路効率で説明すべき差は残っていない**。
- 時間の使い方（60 万回の run）：巡回車の待機は 2004・2016 で日あたり 1〜12%、2001 で 3〜30%。2001 は日境界満タンの反実仮想でもまだ +3.8% あり（2c）、残る余地は燃料・在庫に縛られる盤面に限られる。
- 判断：探索量を増やす方向と、経路構造を変える新方式の試作は**打ち切り**。根拠は 3 盤面・各 2 seed で、盤面数を増やせば別の型が出る可能性は残る（予算上の打ち切り）。

## 4. 実験の実行基盤（`tools/xq.py`）

worktree は merge 後に他セッションの整理で消えることがあり、今回 2 つの計測が実行ファイルごと消えて `exit 1` になった。盤面・道具・実行ファイル・結果は worktree の外（`~/.procon-goal-lab/`）に置き、計測は `xq.py` の待ち行列で回す。

- `xq.py add ID TIMEOUT -- CMD`：ジョブを追記。`xq.py run [並列数]`：未完了だけ実行。`xq.py status`：一覧。
- ジョブごとに timeout（超過は kill して `timeout` と記録）、終了コード、`logs/ID.log`。失敗は記録して自動再試行しない。
- 完了は `queue/done.jsonl` に追記されるので、途中で止まっても `run` をもう一度呼べば続きから再開する。
- これは「止まっても再開できる」ところまでで、セッションが切れたあと自動で次の仮説に進む仕組みではない。再開手順と未完了の作業は Issue #445 のコメントに書く。
