# 補給車が区間の途中で巡回車に合流する（`midleg=on`、Issue #457）

2026-10-11 未明。評価はすべて `players=2`（`docs/research/traffic-calibration-445/` の較正）。基準は `fleet:…:fuel_need=50:fuel_mix=on`、それに `:midleg=on` を足した対比較（同じ盤面・同じ seed・同じ予算）。

## 何が足りなかったか

`fleet` の補給車が巡回車に給油できるのは、巡回車が**訪れるスポットの上**か**止まった地点**だけだった。そのため

- 補給 1 台が 1 日に回せる給油の回数が、スポットで待ち合わせられる回数に縛られる（燃料律速の 32×32 で、燃料項を入れても日境界満タンの反実仮想に B で 3.8% 届かず、巡回車の待機が日あたり最大 30% 残る）。
- タンクだけでは届かない区間は、補給車が同行していない限り計画に入らない（1 回戦第 3 試合の初日 9 系列目がこの形で、`convoy` はこれを取るために作られた）。

## 変更（既定 off、既定の計画は変更前と byte 一致）

`midleg=on` のとき、補給車の合流候補に**巡回車の区間（スポット間の最短路）上のセル**を加える。

1. 補給車がそのセルに先に着いて待てるなら、巡回車は通過するだけで満タンになる（巡回車は 1 tick も止まらない）。区間の残りは満タンから払う。
2. タンクが次の区間に足りなくても、途中のセルまでは届き、そこで補給車が待てるなら出発する。

タイムライン上は「止まらない訪問」として記録し、補給車の停止点はセルで持つ。提出する計画は従来どおり `MatchSim` で再生して検査する。セル間の最速時間の表（全セル対）を日ごとに 1 回作る（32×32 で 1 日の計画あたり約 0.4 秒増）。

`sized` は `midleg=on` を 17 以上の `fleet` 脚にだけ渡す（既定 off）。

参考として残す（`results/v1-*.jsonl`）：32×32 の 22 対で 17/0/5・+1.4%、新規 32×32 の 16 対で 9/1/6・+0.8%（区間 ±3.5）、16×16・24×24 の 60 対で +1.4% だが D が下がる対が 6。届かない区間を扱う 2 を足して初めて D が伸びた。

`midleg` で `fleet` は難盤面の D を +15 伸ばすが、巡回車の 1 日をセル単位で厳密に解く `convoy` との差はまだ埋まらない（2014 の盤面で 51 対 54）。**16×16 は `convoy` のまま**（`sized` の境界 16 を維持）。

## 読み方と限界

- B は探索量固定・holdout・wall-clock のどれでも +2〜2.5%。D は合計では増える（+18、+2）が、個別には下がる対がある（134 対中 7、holdout 32 対中 3）。wall-clock の 6 盤面では D は動かなかった。
- 16×16 の Arena official では差がない（4/0/8、D −1）。16×16 は `sized` が `convoy` に渡すので、この変更が効くのは 17 以上の盤面。
- 実戦では未確認。公式の 59 秒条件では +1.1%（6 盤面・1 seed、有意でない）で、D は動かない。**59 秒で使う限り、期待できるのは B の小さな上積みと「悪化しない」まで**。
- 巡回車が途中で待つ合流、補給 2 台の協調は扱っていない。
