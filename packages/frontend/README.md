# ビジュアライザ

SolidJS + WebGPU製のマップビューアです。WebGPUが使えない環境ではCanvasに切り替わります。

## 起動

Node.js 22.12以降とBunを用意してください。

```sh
cd packages/frontend
bun install --frozen-lockfile
cp .env.example .env.local
# .env.local に coreserver と同じ MATCH_URL / PROCON_TOKEN を設定
bun run dev
```

http://127.0.0.1:5173/live を開くと、接続先の `GET /setting` と `GET /` を1秒ごとに読み取ります。`MATCH_URL` にパスがある場合もそのパス配下を参照します。`Procon-Token` はViteのプロキシが付けるため、ブラウザには渡しません。エージェント登録・回答送信は既存のcoreserverを使ってください。

`base/src/serialize.rs` のJSON形式を読み、地形、系列別スポット、両チームの車両番号・種類・位置、巡回車の残り燃料と上限、日数、ステップ数、回答締切を表示します。通信が途切れた場合は最後の表示を保ち、5秒後にStaleと表示します。データを受信するまではマップを表示しません。スポットの系列記号は6種類を繰り返します。相手車両は同じ記号で表示します。ヘキサのホバー・タップ、またはセル番号入力で、地形・交通状況・スポットの系列と最大在庫・重なっている全車両を確認できます。補給車の燃料は対象外です。現在在庫・獲得玉数・得点はAPIから取得できず、ステップ内の移動も表示しません。

Map / Replayは移植元のサンプルを使った表示です。実試合はLiveを使ってください。接続には開発サーバーが必要です。`bun run build` の静的出力だけではAPIプロキシは動きません。

## 確認

```sh
bun run check
bun run lint
bun run test
bun run build
```

スクリーンショットはチームのJSON形式を返すローカル検証サーバーに接続したLive画面です（実試合の記録ではありません）。

## 実試合ログの録画

練習場からダウンロードしたtrace JSON（`problem` と `teams[].kinds` / `teams[].days[].frames` を含む形式）を用意して実行します。

```sh
bun run record:install
bun run record:match /path/to/trace.json --team 0 --fps 10
```

`../../target/match-video/` に `match.webm`、`match.png`、入力データのSHA-256とフレーム数を記録した `source.json` を出力します。全チームの記録済み位置・燃料をステップ順に表示し、指定したチームの燃料を右側に表示します。移動の補間や未記録フレームの生成は行いません。再生速度は既定10ステップ/秒です。入力ログやチーム名・認証情報は出力にコピーしません。

録画専用の開発サーバーを空きポートで起動し、試合APIへの通信は行いません。`bun run record` はサンプル画面の録画用で、実試合には `record:match` を使ってください。

## 公式の行動例

`/examples/q6` で[公式Q6補足資料の全数値表](https://rebuildup.dev/share/procon2026/#example)を再生できます。8台それぞれの位置・燃料・獲得玉数を、初期状態から最終状態まで39列の順に表示します。これは公式の説明例で、実試合ログではありません。同じ4セルを車両ごとに分け、スポットと車両が重なるセルは車両を優先表示します。Liveでも同じセルに複数の車両がいる場合、自チームの後の車両を優先表示します。

```sh
RECORD_MS=26000 bunx playwright test e2e/official-example.spec.ts
```

録画は `../../target/recordings/official-q6.webm` に出力します。補足資料の説明文と数値表には処理順の表記差があるため、再生には原表の値・列順を使っています。

## 公式動作確認サーバーでの録画

本PRの主要な録画は、公式配布の簡易サーバーをローカルで起動し、2チーム・4日の対戦を実行したものです。一方は1日ごとに左右へ1回移動して残りを待機し、もう一方は待機します。行動の受理revisionと、サーバーが返した日初めの位置・燃料を保存しています。大会・練習場の実戦ログではありません。

```sh
bun run record:live /path/to/procon-server-linux-amd64 /path/to/local-config.json ../../target/live-evidence
```

`local-config.json` は公式配布の `example.json` を使い、`problem.daySeconds` を `[12,12,12,12]`、チームを2つのローカル検証用トークンに設定します。公式サーバーを127.0.0.1:5491で起動するため、このポートを空けて実行してください。手元のサーバーだけに行動を送信し、録画後は起動したプロセスを終了します。トークンは出力に保存しません。

WebGPUの通常表示とCanvasのダーク表示の2本の動画に加え、日ごとの状態、ズーム・パン、モバイル表示、サーバー停止後のStale表示を撮影します。`match-data.json` は実際のHTTP応答、`team-*-plans.json` は提出した行動と受理結果です。APIが返さないステップ内の位置は生成しません。

## 表示と操作

各ページに地形・車両・スポットの凡例を表示します。日数・再生ステップ・巡回車の燃料は、数値と円形表示を併用します。Replaysの再生速度は1×・2×・4×・8×・16×・32×から選択でき、回答の残り時間は `m` / `s` で表示します。

キャンバスを固定し、右のコントロールだけスクロールできます。ホバー詳細はヘキサの隣に固定サイズと列幅で表示します。ホバー・タップしたセルはヘキサ間の白い隙間に青い枠で示し、ポインターが外れると選択を解除します。平地は土色、道路は灰色、山地は緑の横線模様、池は青で表示します。道路の斜線は順調・混雑・渋滞の順に太くなります。巡回車の円は燃料の残量です。店の破線円は現在在庫が取得できないことを示します。詳細表にはPrimer DataTableの公式CSSを使用し、元ソースとライセンスは `src/vendor/primer/` に記録しています。
